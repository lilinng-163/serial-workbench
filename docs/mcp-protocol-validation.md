# MCP 协议开放开关验证

## 2026-10-16 本地后续开发验证

- `read_events` 的 schema 和运行时均要求非空 `channel_id`，空值、串口名称、通配符和无效 ID 不会回退到其他连接；返回值附带 scope、连接 ID、协议和状态。全局历史改用显式的 `read_all_events`，仍遵循协议开放开关。
- 内存中的旧 SSH 与当前 COM8 串口分别读取，确认不混入其他连接数据；新数据游标、独立读者、分页、断开历史和已移除历史均覆盖。COM8 仅是测试配置名称，没有打开实体端口。
- 本机 HTTP 验证漏填 ID 立即报错、指定串口的长轮询忽略 SSH、目标移除或权限关闭时返回错误，不会自动切换连接。
- `read_usage_guide` 提供软件 skill 正文、服务端路径及脚本主题。指南中的 main 示例通过解释器验证半帧、连帧、日志噪声、坏校验与坏帧尾后的重同步；全部协议关闭时仍可读取说明。
- 脚本窗口的 AI 提示词使用当前未保存代码和 HEX 样本，复制不会应用代码或启用脚本。Windows 平台检查浅色、深色及 480×300 窗口，复制和关闭按钮保持可用。
- 10 组 Qt 测试合计 269 项通过、4 项可选环境测试跳过。skill 通过 skill-creator 校验，打包版本通过 HTTP/STDIO 12 个工具联调。
- 本地安装包包含 skill 与参考文件，并纳入精确卸载清单；自定义中文目录安装、原目录升级、个人设置保留、无 SDK 启动、运行中保护、MCP 指南及卸载验证通过。

以上改动随 0.15.16 本地安装包交付，尚未发布；网站和国内镜像保持冻结。使用新增指南工具前，需要安装并运行新版本，再刷新 AI 客户端的 MCP 工具列表。覆盖安装保留原有 MCP 端口及设置。

## 0.15.14 验证记录

本地版本：0.15.14，2026-10-15。网站与发布镜像保持冻结。

「设置 → AI / MCP → 向 AI 开放」提供串口、TCP、UDP、SSH 四个开关。
TCP 客户端和服务端共用 TCP 开关。旧配置默认全部开放，写入和控制仍受原有总权限约束。

## 验证结果

- 四组原有 Qt 测试共 181 项通过，3 项可选测试跳过。
- 新增 `mcp_protocol_tests`：10 项通过，覆盖串口、TCP 客户端、TCP 服务端、UDP、SSH。
- 验证关闭后的连接总览和计数、聚合与单连接历史、波形和 JSON/XML 及脚本读取、发送、建立和关闭连接均遵循开关。
- 混合协议历史以单条分页读取，隐藏记录不占返回页；关闭标签后的历史仍按记录所属协议过滤。
- 关闭协议不影响本地收数和 GUI 历史；重新开放后可重新读取保留的历史。
- 真实本机 HTTP 请求验证长轮询忽略未开放协议的数据，并在指定连接的访问被关闭后及时返回错误。
- 设置控件即时同步并写入文件，重新启动后恢复，TCP 客户端和服务端的设置一致。
- 打包程序通过官方 MCP Python SDK 的 HTTP / STDIO 联调，覆盖独立读者、总写权限、回环收发、分页游标、长轮询和 wave/1 数据。
- 浅色和深色设置页已渲染检查，四个协议开关与提示完整显示。

权限矩阵使用内存会话验证，不连接真实 SSH 主机或实体串口；打包联调使用 `loop://` 和本机网络。
